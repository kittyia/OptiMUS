Background: Amazon Locker is a self-service delivery or pickup location where customers can pick up packages and drop off returns. Some packages are sent with standard shipping speed (3- to 5-day shipping), while other packages are sent with speed shipping (1- to 2-day shipping). The number of days a package will spend in the locker (package dwell time) is generally unknown. We want to decide how many packages to reserve for different ship options to increase the locker throughput.
    
Objective: Maximize the throughput - the total number of packages delivered to the locker in the time horizon

Parameters:
- ShipOptions (): Number of ship options
- PriorDays (): Number of days in prior to current day that packages will still be present in the locker for
- PlanningHorizon (): Number of days in the planning horizon
- LockerCapacity (): Total locker capacity
- DwellTimeProb (ShipOptions, PlanningHorizon, PlanningHorizon): Dwell time probability estimation, the probability that a package belonging to ship option $s$ and delivered on day $v$ will be present on day $t$ where $t>v$
- DwellTimeProbPrior (ShipOptions, PriorDays, PlanningHorizon): Dwell time probability estimation, the probability that a package belonging to ship option $s$ and delivered on day $v$ will be present on day $t$ where $t>v$ for packages present in locker at the end of day 0
- PackagesInLockerDayZero (ShipOptions, PriorDays): Number of packages of ship option $s$ delivered to locker on day $v$ and present in the locker at the end of day $0$
- Demand (ShipOptions, PlanningHorizon): Package demand forecast for package deliveries of ship option $s$ on day $t

Constraints:
- Locker capacity is not violated in any period of the planning horizon
- For any period of the planning horizon, the number of packages of any ship option accepted for delivery is less than or equal to demand for that ship option
- Define the relationship between the number of packages accepted for delivery and the number of slots reserved for the ship option
- The decision variables are constrained to be nonnegative by constraints
