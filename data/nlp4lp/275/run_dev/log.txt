### Why?

The problem describes a **multi-commodity flow** setting:
- Each source-destination pair represents a separate commodity.
- Data can be split across multiple paths.
- Nodes can forward data through intermediate nodes.

To correctly model routing behavior, we must enforce **flow conservation** for each commodity at every node.

### What this constraint enforces

For each source-destination pair \( k \) and node \( i \):

\[
\sum_{j} f_{i,j}^{k} - \sum_{j} f_{j,i}^{k}

\begin{cases}
d_k & \text{if } i = \text{source of } k \\

- \( f_{i,j}^{k} \) is the flow of commodity \( k \) on arc \( (i,j) \)
- \( d_k \) is the required data amount for pair \( k \)

### Why it is necessary

Without this constraint:
- Flow could disappear or be created arbitrarily at intermediate nodes.
- The model would not guarantee that the required data actually reaches its destination.
- The solution would not represent a valid routing of data.

This constraint is **fundamental** in all network flow formulations (single-commodity and multi-commodity). It must be explicitly modeled.

The decision variables in this problem will represent something like:

\[
f_{i,j}^{k}
\]

\[
f_{i,j}^{k} \ge 0 \quad \forall i,j,k

- Non-negativity is often specified as a variable bound.
- Even if some modeling languages assume variables are nonnegative by default, mathematically it **is still part of the model**.
- Omitting it would fundamentally change the feasible region.

This is a standard and essential constraint in multicommodity flow problems.
